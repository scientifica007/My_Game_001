# حُماة الواحة — Oasis Defenders

لعبة استراتيجية عربية من نوع الدفاع عن الأبراج، تشمل **3 مستويات و15 موجة** مع خرائط متعددة وتصاعد للصعوبة وإدارة الذهب وترقية الأبراج.

**البنية التقنية الحالية:** Vite + JavaScript ES Modules + HTML + CSS + Canvas. لا توجد قاعدة بيانات أو خدمة خلفية أو اشتراك مدفوع. يعمل محرك اللعبة في المتصفح؛ Vite مطلوب للتطوير وبناء الملفات الإنتاجية فقط.

## تشغيل المشروع على Ubuntu / Linux

المتطلبات: Node.js 20.19 أو أحدث من سلسلة 20، أو Node.js 22.12 أو أحدث، وnpm. يوصى بـ Node.js 22 LTS.

```bash
git clone https://github.com/scientifica007/My_Game_001.git
cd My_Game_001
git fetch origin
git switch --track origin/refactor/vite-modular-engine
npm install
npm run dev
```

افتح العنوان الذي تعرضه الطرفية (عادة `http://127.0.0.1:5173/`). بعد تثبيت الاعتماديات أول مرة، يمكن تشغيل التطوير محليًا دون الحاجة للإنترنت.

للبناء والتحقق والتجربة الإنتاجية:

```bash
npm test
npm run build
npm run preview
```

يوجد الناتج في مجلد `dist/`. **لا تفتح `index.html` مباشرةً بالنقر المزدوج**: تستعمل هذه النسخة ES Modules، والأفضل تشغيلها من خادم تطوير محلي أو تقديم ملفات `dist` عبر خادم HTTP ساكن. ملفات اللعبة التي ينشئها البناء لا تتطلب Vite عند تشغيلها من خادم ثابت.

### ما الذي تغيّر عن ملف HTML الواحد؟

- `index.html` يحمل عناصر الصفحة فقط؛ CSS وJavaScript في ملفات مستقلة.
- يتواصل `main.js` مع وحدات واجهة المستخدم والمحاكاة والرسم عبر وظائف مستوردة وممرر حالة مشترك.
- وضعت قواعد أرقام المراحل والأعداء والاقتصاد في وحدات مستقلة ليسهل تعديل التوازن واختباره.
- ينتج Vite ملفات إنتاجية قابلة للنشر على استضافة ملفات ثابتة، لكنه **لا ينشرها تلقائيًا**.
- الاحتفاظ بواجهة Canvas خفيفة يحول دون تحميل إطار واجهات ثقيل لا تحتاجه اللعبة.

## قواعد اللعب الحالية

| العنصر | المستوى 1 | المستوى 2 | المستوى 3 |
|---|---:|---:|---:|
| الموجات | 5 | 5 | 5 |
| عدد الأبراج الأقصى | 8 | 7 | 6 |
| مضاعف صحة العدو | 1× | 1.9× | 3.4× |
| الخريطة | متعرجة | مختلفة | أقصر |

تزداد قوة وسرعة وأعداد الأعداء داخل المستوى نفسه، وتنتهي كل خمس موجات بقائد قوي. تُعاد الأبراج إلى الصفر عند الانتقال إلى مستوى جديد، وتتوفر ميزانية جديدة محدودة تتضمن مكافأة ادخار جزئية، مع استعادة 3 نقاط صحة بحد أقصى 12.

**الأبراج:** سهام (55 ذهبًا)، قذائف (95 ذهبًا)، رياح لإبطاء الأعداء (80 ذهبًا). يمكن ترقية الأبراج وبيعها. لكل عدو مقاومات مختلفة ضد بعض أنواع الهجوم.

**اختصارات لوحة المفاتيح:** `1` و`2` و`3` لاختيار البرج؛ `Space` لبدء الموجة؛ `P` للإيقاف والاستئناف؛ `F` لمضاعفة السرعة.


## تحسينات العالم البصري (Living Oasis)

- **ثلاث هويات لونية للمستويات:** رمال الواحة، ممر صخري دافئ، ثم أرض الحصار بألوان الغسق.
- **طبقات تضاريس:** تموجات رملية، صخور ونباتات، طريق بارز الحواف، جبال بعيدة وضوء الشمس.
- **واحة حية:** ماء متلألئ وتموجات خفيفة وأشجار نخيل تتحرك ببطء وغبار ينساب في الهواء.
- **كائنات مميزة:** لكل من العادي والسريع والثقيل والقائد هيئة وألوان وتجهيزات مختلفة؛ حركة أطراف، اهتزاز جسم، رمش عين ووميض عند تلقي الضربات.
- **أبراج حيوية:** ارتداد عند الإطلاق، دوران برج الرياح، وهج المقذوفات وآثار حركة قصيرة.
- **مراعاة الأداء:** تُرسم التضاريس الساكنة مرة واحدة لكل خريطة على Canvas مساعد؛ لا صور أو خطوط خارجية. تتوقف الزخارف المتحركة عند تفعيل تفضيل النظام `prefers-reduced-motion`.

كل هذه التحسينات رسومية؛ لا تغيّر قيم الضرر أو اقتصاد الذهب أو شروط الفوز والخسارة. يختبر `tests/visual.test.mjs` التخزين المؤقت وأشكال الوحدات والرسم مع إعداد تقليل الحركة.

## التطوير البصري التالي — Visual Depth V2

هذه نسخة تطويرية أحدث من إصدار **v0.3.0** الموثق في `RELEASE-READINESS.md`، ولا تغيّر مرجع الإصدار المحفوظ `baseline/release-ready-v0.3.0`.

- **إضاءة بيئية متغيرة:** صباح الواحة، حرارة الممر الصخري، وغسق المستوى الثالث.
- **حركة الجو:** شرائط ضوء شفافة، حرارة متموجة، وجسيمات مضيئة في الغسق.
- **شخصيات أكثر تعبيرًا:** آثار سرعة خلف العدو السريع، وهالة قائد متغيرة، ومؤثرات هواء حول البرج الدوار.
- **تبديل الجودة:** زر `✨ مؤثرات غنيّة` يتيح الانتقال إلى `🌿 مؤثرات اقتصادية`. يحفظ الاختيار محليًا عندما يسمح المتصفح بذلك؛ في الوضع الاقتصادي تُعطّل بعض الإضاءة والجسيمات والحركات الزخرفية لتخفيف الحمل.
- **حفاظ على القواعد:** لا تتغير حركة الأعداء الفعلية أو قوة الأبراج أو شروط الانتقال عند الخسارة. يشمل التحقق اختبارات تمنع تغيّر حالة اللعب عند تبديل الجودة.

## الوحوش الحية — Living Creatures V3

تعرض النسخة البصرية الحديثة أربعة أنواع من الأعداء تختلف في **الشكل الخارجي والبنية والحركة**:

- **العادي — خنفساء الصحراء:** جسم بيضوي ذو جناحين منفصلين، 6 أرجل بالتبادل، فكّان وقرنا استشعار متحركان.
- **السريع — عدّاء الكثبان:** هيئة طويلة وذيل مرن يتلوى، 4 أطراف تجري بالتبادل وزعانف ظهرية، مع خطوط سرعة.
- **الثقيل — الحصن المدرّع:** جسم عريض ودرع مكوّن من ثلاث صفائح، 4 أرجل مفصلية ثقيلة وقرنان، وحركة بطيئة للألواح.
- **القائد — العملاق المتوّج:** قرون كبيرة، أجنحة غشائية متأرجحة، 4 أطراف قوية، قطع عائمة وهالة متحركة.

ترتبط وضعية أجسام الأعداء باتجاه الطريق نفسه، ولا يتأثر الضرر أو السرعة أو نظام الفوز والخسارة بهذه الرسوم. يجمّد إعداد «مؤثرات اقتصادية» حركة الأطراف الزخرفية، كما يُحترم تفضيل تقليل الحركة.

وُضع الرسم في `src/creatures.js` مع الحفاظ على واجهة `drawEnemySprite` في `src/sprites.js`؛ تراجع `tests/creatures.test.mjs` تميّز الأشكال وتحرك أطراف الجسم وثباتها عند تقليل الحركة وعدم تغيير بيانات اللعبة.

## وضوح ممر الوحوش — Road Contrast

فُصل الطريق عن الأرض الصحراوية بثلاثة ألوان حسب المستوى، مع حافة حجرية فاتحة عالية التباين، وظل تماس داكن أسفل البلاط، وملمس داخلي، وخط متقطع متصل يظهر اتجاه الممر عند المنعطفات.

يُنفّذ ذلك في `src/landscape.js` عبر `ROAD_THEMES` من دون تعديل المسار أو أماكن الأبراج أو سلوك الأعداء. وتُرسم البلاطات ضمن طبقة التضاريس الثابتة المخزنة مؤقتًا، بحيث لا يزيد هذا التأثير تكلفة الرسم في كل إطار. يفحص `tests/road.test.mjs` تباين حواف الطريق وألوان المستويات الثلاثة وسلامة بيانات المسارات.

## جودة المشروع واختباراته

`npm test` ينفذ اختبارات بناء ملف JavaScript المجمّع ومحاكاة اللعب دون متصفح رسومي، بما يشمل التدرج والحركة والترقية والبيع وانتقال المستويات والاقتصاد، والتمييز بين التوزيع الاستراتيجي والجيد والتوزيع السيئ في المستوى الثالث.

`npm run build` يتحقق من قدرة Vite على إنتاج نسخة متكاملة. تنفَّذ الأوامر آليًا عبر GitHub Actions عند كل Push أو Pull Request.

الاختبارات الآلية لا تعوض الاختبار اليدوي على Firefox أو Chromium، ولا تقيس كل الاحتمالات الممكنة في التوازن.

## سياسة المشروع

- `main`: الإصدار المستقر السابق، لا يتغير حتى المراجعة والدمج.

- `refactor/vite-modular-engine`: هذه الهندسة الحديثة، مبنية على الفرع السابق.

لا تفعيل لـ GitHub Pages ولا نشر عام عبر الموقع ضمن هذه المرحلة. يمكن مراجعة هذه الهندسة ودمجها مستقلًا قبل دمج الحملة النهائية في `main`.
