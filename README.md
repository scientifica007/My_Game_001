# حُماة الواحة — Oasis Defenders

لعبة استراتيجية عربية من نوع الدفاع عن الأبراج، تشمل **3 مستويات و15 موجة** مع خرائط متعددة وتصاعد للصعوبة وإدارة الذهب وترقية الأبراج.

**البنية التقنية الحالية:** Vite + JavaScript ES Modules + HTML + CSS + Canvas. لا توجد قاعدة بيانات أو خدمة خلفية أو اشتراك مدفوع. يعمل محرك اللعبة في المتصفح؛ Vite مطلوب للتطوير وبناء الملفات الإنتاجية فقط.

## تشغيل المشروع على Ubuntu / Linux

المتطلبات: Node.js 20.19 أو أحدث من سلسلة 20، أو Node.js 22.12 أو أحدث، وnpm. يوصى بـ Node.js 22 LTS.

```bash
git clone https://github.com/scientifica007/My_Game_001.git
cd My_Game_001
git fetch origin
git switch --track origin/refactor/vite-modular-engine
npm install
npm run dev
```

افتح العنوان الذي تعرضه الطرفية (عادة `http://127.0.0.1:5173/`). بعد تثبيت الاعتماديات أول مرة، يمكن تشغيل التطوير محليًا دون الحاجة للإنترنت.

للبناء والتحقق والتجربة الإنتاجية:

```bash
npm test
npm run build
npm run preview
```

يوجد الناتج في مجلد `dist/`. **لا تفتح `index.html` مباشرةً بالنقر المزدوج**: تستعمل هذه النسخة ES Modules، والأفضل تشغيلها من خادم تطوير محلي أو تقديم ملفات `dist` عبر خادم HTTP ساكن. ملفات اللعبة التي ينشئها البناء لا تتطلب Vite عند تشغيلها من خادم ثابت.

## هيكل الملفات

```text
My_Game_001/
├── index.html                 # هيكل الواجهة العربية
├── src/
│   ├── main.js                # تنسيق دورة اللعبة والأحداث والحالة العامة
│   ├── config.js              # الخرائط والثوابت وإعدادات الأبراج
│   ├── levels.js              # حساب قوة وسرعة ومكافآت الأعداء
│   ├── economy.js             # الترقية والبيع ومكافآت الموجات والمستويات
│   ├── simulation.js          # حركة الأعداء والقتال ونتائج الموجة
│   ├── renderer.js            # رسم Canvas والخريطة والوحدات والمؤثرات
│   ├── ui.js                  # واجهة المستخدم والرسائل ومعلومات الأبراج
│   └── styles.css             # التصميم المتجاوب
├── tests/
│   ├── game.test.mjs          # اختبارات التكامل والوظائف الأساسية
│   └── campaign.test.mjs      # اختبارات المراحل والتوازن والموارد
├── vite.config.js             # إعداد البناء النسبي
└── .github/workflows/check.yml
```

### ما الذي تغيّر عن ملف HTML الواحد؟

- `index.html` يحمل عناصر الصفحة فقط؛ CSS وJavaScript في ملفات مستقلة.
- يتواصل `main.js` مع وحدات واجهة المستخدم والمحاكاة والرسم عبر وظائف مستوردة وممرر حالة مشترك.
- وضعت قواعد أرقام المراحل والأعداء والاقتصاد في وحدات مستقلة ليسهل تعديل التوازن واختباره.
- ينتج Vite ملفات إنتاجية قابلة للنشر على استضافة ملفات ثابتة، لكنه **لا ينشرها تلقائيًا**.
- الاحتفاظ بواجهة Canvas خفيفة يحول دون تحميل إطار واجهات ثقيل لا تحتاجه اللعبة.

## قواعد اللعب الحالية

| العنصر | المستوى 1 | المستوى 2 | المستوى 3 |
|---|---:|---:|---:|
| الموجات | 5 | 5 | 5 |
| عدد الأبراج الأقصى | 8 | 7 | 6 |
| مضاعف صحة العدو | 1× | 1.9× | 3.4× |
| الخريطة | متعرجة | مختلفة | أقصر |

تزداد قوة وسرعة وأعداد الأعداء داخل المستوى نفسه، وتنتهي كل خمس موجات بقائد قوي. تُعاد الأبراج إلى الصفر عند الانتقال إلى مستوى جديد، وتتوفر ميزانية جديدة محدودة تتضمن مكافأة ادخار جزئية، مع استعادة 3 نقاط صحة بحد أقصى 12.

**الأبراج:** سهام (55 ذهبًا)، قذائف (95 ذهبًا)، رياح لإبطاء الأعداء (80 ذهبًا). يمكن ترقية الأبراج وبيعها. لكل عدو مقاومات مختلفة ضد بعض أنواع الهجوم.

**اختصارات لوحة المفاتيح:** `1` و`2` و`3` لاختيار البرج؛ `Space` لبدء الموجة؛ `P` للإيقاف والاستئناف؛ `F` لمضاعفة السرعة.

## جودة المشروع واختباراته

`npm test` ينفذ اختبارات بناء ملف JavaScript المجمّع ومحاكاة اللعب دون متصفح رسومي، بما يشمل التدرج والحركة والترقية والبيع وانتقال المستويات والاقتصاد، والتمييز بين التوزيع الاستراتيجي والجيد والتوزيع السيئ في المستوى الثالث.

`npm run build` يتحقق من قدرة Vite على إنتاج نسخة متكاملة. تنفَّذ الأوامر آليًا عبر GitHub Actions عند كل Push أو Pull Request.

الاختبارات الآلية لا تعوض الاختبار اليدوي على Firefox أو Chromium، ولا تقيس كل الاحتمالات الممكنة في التوازن.

## سياسة المشروع

- `main`: الإصدار المستقر السابق، لا يتغير حتى المراجعة والدمج.
- `feature/wind-tower-strategy`: الحملة الاستراتيجية مع فصل HTML/CSS/JS الأولي.
- `refactor/vite-modular-engine`: هذه الهندسة الحديثة، مبنية على الفرع السابق.

لا تفعيل لـ GitHub Pages ولا نشر عام عبر الموقع ضمن هذه المرحلة. يمكن مراجعة هذه الهندسة ودمجها مستقلًا قبل دمج الحملة النهائية في `main`.
