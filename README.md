# حُماة الواحة — Oasis Defenders

**نسخة تطويرية: حملة استراتيجية من 3 مستويات × 5 موجات (15 موجة).**

لعبة دفاع عن الأبراج (Tower Defense) باللغة العربية، مبنية بملفات HTML وCSS وJavaScript منفصلة. تعمل مباشرة في Firefox أو Chromium أو Chrome، دون تبعيات خارجية أو اتصال بالإنترنت.

## طريقة اللعب

1. نزّل المشروع كاملًا مع المجلد `assets`، وافتح `index.html`، ثم اضغط «ابدأ التخطيط». يمكن أيضًا استعمال خادم تطوير محلي عند الرغبة.
2. ابْنِ دفاعاتك خارج الطريق، وراقب الذهب وصحة الواحة وعدد الأبراج المسموح.
3. أطلق الموجة الأولى، ثم عزز دفاعاتك أو حسّن توزيعها بين الموجات.
4. بعد الموجة الخامسة في كل مستوى تظهر خريطة جديدة؛ لا تنتقل الأبراج القديمة، بل تحصل على ميزانية تجديد محدودة واستعادة جزئية لصحة الواحة.
5. للفوز، يجب الصمود في **المستويات الثلاثة وجميع الموجات الخمس عشرة**.

## تصاعد الصعوبة

| الخاصية | المستوى 1: حدود الواحة | المستوى 2: الممر الصخري | المستوى 3: حصار الواحة |
|---|---|---|---|
| عدد الموجات | 5 | 5 | 5 |
| الحد الأقصى للأبراج | 8 | 7 | 6 |
| صحة الأعداء الأساسية | ×1 | ×1.9 | ×3.4 |
| تصميم الطريق | كثير الالتواءات | جديد | أقصر وأكثر مباشرة |
| أنواع التحديات | سرعة الانتشار الأولي | مقاومة أعلى وأعداء أكثر | ضرورة الترقية وانتقاء المواقع |

داخل كل مستوى ترتفع قوة الأعداء وسرعتهم وعددهم بوتيرة تصاعدية. تضم الموجة الخامسة **قائدًا** ذا صحة عالية يسبب 4 نقاط ضرر إذا وصل إلى الواحة. تضعف فاعلية السهام ضد المدرّعين، وتنخفض فاعلية القذائف ضد الأعداء السريعين، وتقاوم الوحدات الثقيلة والقادة الإبطاء جزئيًا.

**الاقتصاد:** التكاليف والترقيات تتطلب الذهب؛ يُمنح ذهب عند قتل الأعداء واجتياز الموجات. لا تُنقل الأبراج بين المستويات. تُصرف في بداية المستوى التالي ميزانية أساسية مع مكافأة ادخار صغيرة ومحدودة بحد أقصى 265 ذهبًا. تُستعاد 3 نقاط صحة بحد أقصى 12. تنخفض مكافآت قتل الأعداء في المستويين الثاني والثالث مقارنة بقوتهم، مما يفرض الاختيار بين شراء برج جديد وترقية برج قائم. يمكن الفوز أو الخسارة؛ والبناء العشوائي أو التبذير يؤديان غالبًا إلى نفاد القدرة الدفاعية.

## الوحدات والتحكم

| البرج | التكلفة | الدور |
|---|---:|---|
| السهام | 55 | ضرر سريع ومركّز؛ أقل فاعلية ضد المدرّعين |
| القذائف | 95 | ضرر جماعي؛ أقل فاعلية ضد الأعداء السريعين |
| الرياح | 80 | ضرر خفيف مع إبطاء الحركة؛ يقاومه الأعداء الثقيلون جزئيًا |

يمكن ترقية كل برج إلى المستوى الثالث، أو بيعه واسترداد جزء من الذهب. أثناء المعركة يمكن استخدام زر إيقاف أو تسريع اللعب ×2.

**الاختصارات:** `1` السهام؛ `2` القذائف؛ `3` الرياح؛ `Space` إطلاق الموجة؛ `P` إيقاف/متابعة؛ `F` سرعة المعركة.

## الاختبارات

```bash
node --test tests/*.test.mjs
```

يقوم GitHub Actions بتنفيذ الاختبارات تلقائيًا عند التعديل وعند فتح طلبات الدمج. تشمل الاختبارات تحقق بناء JavaScript، وبناء برج الرياح وإبطائه الأعداء، وتفاوت قوة الأعداء بين المستويات والموجات، والهزيمة عند إهمال الدفاع، وقيود البناء، وإعادة تعيين الخريطة والميزانية بين المستويات. يوجد أيضًا اختبار مرجعي للاستراتيجية الموزعة في المستوى الثالث، واختبار يثبت خسارة الاستراتيجية سيئة التوزيع.

**حد الاختبارات:** اجتياز الاختبارات الآلية لا يعني أن توازن اللعبة قد ثُبت لكل استراتيجية. يلزم أيضًا اختبار لعب بشري لمراجعة صعوبة المستويات وتحديد الموارد المناسبة.

## بنية المستودع

- `index.html`: هيكل الواجهة وعناصر التحكم العربية فقط.
- `assets/styles.css`: جميع الأنماط والاستجابة لأحجام الشاشات.
- `assets/game.js`: منطق اللعبة وحالتها والرسوم المتحركة والتفاعل.
- `tests/game.test.mjs`: اختبارات الوظائف الأساسية والتأكد من ربط ملفات الواجهة.
- `tests/campaign.test.mjs`: اختبارات الحملة والصعوبة والموارد.
- `.github/workflows/check.yml`: الفحص التلقائي.
- `README.md`: هذه الوثيقة.

## سياسة التطوير

الأولوية **للعب والاستراتيجية واستقرار الشيفرة**. نعمل على فرع مستقل ونراجع طلب الدمج ونحافظ على الفرع `main` مستقرًا. نشر اللعبة على الإنترنت **مؤجل** إلى قرار منفصل.

## لماذا لم نستعمل React أو خادمًا خلفيًا؟

هذه لعبة Canvas تعتمد على محاكاة تعمل بالكامل في المتصفح؛ ليست تطبيق حسابات أو بيانات مشتركة بين المستخدمين. لذلك لا نحتاج في هذه المرحلة إلى React أو خادم أو قاعدة بيانات. فصل الملفات يُحسن الصيانة والاختبارات مع الحفاظ على خفة التشغيل.

**التدرج المعماري المقترح:** المرحلة الحالية فصل HTML/CSS/JavaScript. عند زيادة عدد الأنظمة سنفصل `game.js` إلى وحدات للبيانات وقواعد الاقتصاد ومحرك المحاكاة والرسم وواجهة المستخدم، مع اعتماد ES Modules وأداة بناء خفيفة عند الحاجة. يمكن اختبار هذه النقلة على فرع مستقل دون خسارة نسخة اللعب المستقرة.

**ملاحظة تشغيل:** لم يعد نقل `index.html` وحده كافيًا؛ يجب إبقاء ملفَّي `assets/styles.css` و`assets/game.js` بجواره ضمن هيكل المجلدات.
